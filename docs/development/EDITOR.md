# Editor and restoration

Aether has a dedicated IDE workspace with **Back to Aether**, a full Code-OSS workbench on the left, and project-scoped Ava chat on the right. The agent pane can collapse; Code-OSS provides its normal Explorer, source control, terminal, panels, commands and extension management. The regular Aether header also exposes the project folder and IDE/terminal entry point.

**Full IDE** installs pinned [code-server 4.141.0](https://github.com/coder/code-server/releases/tag/v4.141.0), a distribution of the VS Code open-source workbench. Setup shows size/progress, checks free space and the pinned SHA-256 digest, rejects archive path escapes, and installs into private application data. Runtime assets download on request rather than being embedded in every Aether package. The first workbench preferences match Aether's light/dark mode, disable its separate AI chat and telemetry, and preserve subsequent user customization. Workspace trust remains enabled.

The runtime binds a random loopback port with a random session password, private config and extension/user directories. Main authenticates a separate browser session. Its native WebContentsView has no Aether preload, Node integration or main-app bridge. Validated project IDs and viewport bounds are the only renderer controls for this view; arbitrary URLs/commands are not accepted through this IPC. Links open externally only for HTTPS. Returning to Aether hides the workbench and preserves open editors/terminal jobs; quitting stops its process group.

Unix runtime IPC uses a short private temporary directory to stay within Unix socket-path limits even when userData has a long path. Setup aborts download/extraction during quit and removes staging files; runtime shutdown removes that private socket directory. Failed setup can be retried. Failed startup retries the installed runtime without redownloading it.

Extraction uses the operating system's archive tool by absolute path, with a system-only helper PATH on Unix, rather than a terminal-specific PATH inherited by a desktop launch. It suppresses macOS copyfile metadata restoration, does not restore archive ownership, and allows ten minutes for large archives. Stale download/staging files are removed before the free-space check. Disk exhaustion and permission failures explain the recovery action; other failures retain bounded diagnostics. A saved manifest alone cannot mark a runtime ready when its executable or entry point is missing.

Verification: `AETHER_IDE_ARCHIVE=/absolute/path/to/the/pinned/platform-release.tar.gz npm run test:ide` exercises a real fresh install on macOS arm64. The fixture saves a file, executes a terminal command, installs/activates a locally generated VSIX through the official runtime CLI, confirms its file output, opens the installed-extension UI, selects a model from a local HTTP catalog, chats with project excerpts, collapses/restores the agent pane, checks narrow-window popup placement, and returns to Aether. The chat endpoint is a deterministic local fixture; it does not establish provider account connectivity. Windows/Linux asset hashes are pinned, but their runtime behavior has not been tested here. The script uses the system `zip` tool to assemble its disposable VSIX fixture.

Extensions install through Code-OSS from **Open VSX** or a **VSIX** file. The real extension host supports compatible VS Code extensions, including user-selected native extensions; those extensions and interactive terminals have normal local IDE capabilities. This is separate from Aether's scoped provider execution and reviewed plans. Microsoft's proprietary distribution, Marketplace licensing and Microsoft-only extensions are not bundled or guaranteed compatible. See [code-server's FAQ](https://coder.com/docs/code-server/FAQ) for upstream extension differences. Aether does not claim universal Marketplace parity.

**Quick editor** uses Monaco Editor 0.57.0, Microsoft's standalone editor generated from VS Code revision `6a598d4a13031703d483d103c1d934a36ad27971`. It loads locally when opening a file, including local editor/TypeScript/JSON workers. Search, folding, syntax highlighting, completion and Ctrl/Cmd S operate in this lightweight option; it has no extension host. The optional external VS Code handoff remains available. The following file/history limits apply to this quick editor; full Code-OSS uses its normal file and timeline behavior.

The file explorer supports filtering and remembered collapse controls. Sensitive paths, escaping symlinks, binary files and files over 200,000 characters are rejected. Reads for editing preserve exact content rather than saving a redacted preview over the original file. Each save supplies the content revision it read; mismatches block stale overwrites.

Private application records retain the previous content before each save, bounded to 20 snapshots per project. File history offers restoration with confirmation, preserves the current saved content as another snapshot, and checks the current revision. These snapshots stay in application data, never in the project repository or provider context. Older saves made before this feature have no snapshot.

Newly applied agent sessions persist version-1 application evidence: baseline HEAD, changed paths, content fingerprint and application time. “Restore previous version” reverses that session's patch only after the current HEAD and all affected file contents still match the recorded evidence. Affected files with newer changes block restoration. Unrelated files remain intact. This does not reset Git history or force-push; the session retains its original execution and restore events. Historical sessions without application evidence do not expose restore.

UI menus are portaled to a viewport-bounded fixed overlay and close on outside click or Escape. Dialogs use a higher layer and notifications stay readable above dialogs. Native title tooltips remain available for icon actions. Navigation, activity, explorer and inspector section preferences use versioned local-storage keys.
